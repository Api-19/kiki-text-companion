# 分享模式离线语境习惯卡

`scripts/build_habit_card.py` 从已过滤的训练片段库生成卡，由
`scripts/setup_share.py` 的现有调用接入。生成过程只做本地统计和固定模板编译，
零 provider 调用，不增加第三方依赖，不使用验收留出集。

## 卡的两部分

1. **全局形态**：保留原来的首句、6 条统计及“不足 30 条”提醒，措辞不变。
   继续使用 `style_surface_stats.summarize`，统计回复消息条数、总字数、短回复、
   句末语气词、标点及表情。为兼容旧卡，这部分仍按输入片段逐条统计。
2. **语境习惯**：有合格证据时追加固定标题
   `- 不同情况下的接话习惯（倾向，不是每次都这样）：`，其下最多 6 条子项。
   每类最多一条，只列达到差异门槛的行为，显示该类独立事件总数；比例另列命中数/分母。
   没有合格子项时，标题与整个部分都省略，输出与旧卡一致。

示例仅展示模板，不取自任何聊天：

```text
  - 对方提问时：回复更短（约 2 字，整体约 8 字），不超过 4 字的短回复更多（100%，整体 20%，5/5 段）；支持 5 段。
```

语境子项只能由类别名、数字和固定行为短语组成，不拼接片段原文、昵称、专名或例句。
内部结构化证据包含类别、组内及全局统计、命中数/事件分母、互补数（分母减命中数）及
来源规则版本 `habit-contexts-v1`；不生成额外证据文件，不把事件 ID 写入卡。

## 分类规则

只读取片段的 `partner_turns`，即被模仿者回复前最后一段连续的对方消息。
将其中各条消息以换行连接后匹配关键词，不读取 `context_turns` 作分类，
也不从 `owner_reply` 反推语境。关键词直接做包含匹配。

| 类别 | 机械规则 |
| --- | --- |
| 提问 | 去掉末尾空白后以 `？` 或 `?` 结尾；或含“吗”“呢”“怎么”“为什么”“什么”“几点”“要不要”任一词 |
| 连发 | `partner_turns` 条数 ≥ 3 |
| 告别/睡前 | 含“晚安”“睡了”“拜拜”“先忙”“去睡”任一词 |
| 问候 | 含“早安”“早上好”“在吗”“在干嘛”任一词 |
| 情绪低落 | 含“难受”“累”“烦”“哭”“不开心”“好困”任一词 |
| 分享 | 前五类均未命中，且对方消息合计非空白字符数 ≥ 12，作为兜底类 |
| 未分类 | 其余情况，包括没有对方消息；不输出规则 |

前五类允许多标签，例如“在吗”同时命中提问和问候；分享不与其他标签并存。
字符长度采用现有形态统计口径：去掉空白后的 Unicode 字符数，包含标点、emoji 等，
不是中文分词、字素或语义长度。消息边界不会合并出跨消息关键词。

## 独立事件、差异门槛与裁剪

语境部分按 `(conversation_id, started_at)` 去重，同键只保留输入中的首个片段。
类别支持数和用于比较的全局基线都基于这个独立事件集合；基线包含该类别自身和未分类事件。
不同会话即使时间相同也各算一次。同一个事件可支持多个类别，不能将各类支持数相加当作样本总数。
这与兼容保留的全局形态部分按片段计数的口径有所区别。

每类须至少 5 个独立事件，并至少有一个指标达到下表门槛，才生成子项。
组内形式统计继续复用 `summarize`；问句、表情按“事件是否命中”计数，不按标点或表情个数计数。

| 指标 | 口径 | 相对全局基线的门槛 |
| --- | --- | --- |
| 回复总字数中位数 | 同一回复各条消息的非空白字符数之和 | 差异 ≥ 基线的 30% |
| 回复消息条数中位数 | `owner_reply` 条数 | 差异 ≥ 基线的 30% |
| 以问句结尾比例 | 整段回复去掉末尾空白后以 `？` / `?` 结尾 | 绝对差 ≥ 15 个百分点 |
| 含表情比例 | 任意消息含 emoji、颜文字、`[表情]` 类贴纸，匹配复用现有词典规则 | 绝对差 ≥ 15 个百分点 |
| ≤4 字短回复比例 | 整段回复非空白字符数 ≤4 | 绝对差 ≥ 15 个百分点 |

门槛先用未取整的值判定，比例展示四舍五入至整数百分比，中位数保留必要的一位小数。
中位数相同不生成差异；基线中位数为 0 时，仅组内非零才生成差异。
“支持 N 段”指满足语境的独立事件数；`k/N` 指其中命中该行为的事件数，
其余 `N-k` 段保留为互补计数，不承诺每次都如此。更短/更长、更多/更少均可输出。

子项按支持数从高到低排列，同支持数按表中前六类顺序排列。
全卡采用保守的 **600 个 Unicode 字符上限**（含标点、空白、换行和数字，因而汉字也不超过 600）。
超出时逐条删除支持数最低的子项；同支持数先删除类别顺序靠后的子项，
不截断文字或改写全局部分。删光后标题也省略。

## 接口与输出

`build_habit_card(snippets, lexicon, *, scenario: Literal["companion", "generic"] = "companion") -> str`。
分享模式经 `setup_share.py` 调用，使用默认的 companion 模板。
`scenario="generic"` 仅将首句替换为：

```text
以下是从训练集 {n_replies} 条回复中自动统计的表达形式，只描述形式，不代表性格。
```

首句之后的固定措辞、低样本提醒、统计、事件去重、分类、差异门槛、排序和裁剪均不变；
600 字符预算按实际全文计算，首句长度可能改变保留的语境子项数。

输出使用独占创建 `O_EXCL`、权限 `0600`、LF 换行；空库失败；stdout 只打印
`n_replies` / `low_n` 计数，不打印卡或原文。

合成测试覆盖旧全局卡逐字兼容、六类数字、关键词和多标签、支持/差异边界、事件去重、
事件比例、表情类型、600 字符及六条限制和裁剪顺序。
隐私测试对每条 `partner_turns` / `owner_reply` / `context_turns` 原文的所有
4 字符窗口检查输出不含该窗口，因此也排除更长连续原文；该测试使用不会与模板重合的合成原文。

## 局限

**只描述形式和倾向，不代表像不像本人。**
关键词可能误判、漏判，例如否定语句仍会命中；“分享”仅表示足够长且未命中其他规则，
“情绪低落”也只是可见词命中，不是心理状态判断。5 段和差异门槛是初始证据筛选值，
不是统计显著性或因果关系证明；稀疏类别和没有明显差异的类别会缺席。
长度、问号和表情无法判断理解是否正确、承接是否恰当，也不推断性格、关系动机、生活事实或当前状态。
合成测试通过只证明实现符合上述规则，不证明真实效果。
